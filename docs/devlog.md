# 빠따넷 개발 일지

MLB·MiLB 성적과 자체 계산 세이버매트릭스를 보여주는 정적 사이트 **빠따넷**의 개발 기록이다.
Git 커밋 기록과 [`PRD.md`](../PRD.md)를 바탕으로 정리했다. 시각은 한국 시간이다.
결과만 짧게 보려면 [변경점](changelog.md), 알려진 한계는 [보완점](improvements.md)을 본다.

- 사이트: https://raysmc517.github.io/bbaddanet/
- 구조: Python으로 수집·계산 → JSON 저장 → HTML/CSS/JavaScript가 JSON을 읽어 표시 (서버·DB·프레임워크 없음)
- 기록 기간: 2026-11-16(월) ~ 2026-11-20(금)

- 그래서 두 리그 수집기는 승인을 받거나 다른 출처를 찾을 때까지 보류했다. 계획보다 데이터 이용 조건을 먼저 지키기로 한 결정이다.

### 밤: 문서 정리, 입단 경로 확장, 약물 징계 표시

**문서 정리**
- 개발 일지를 쓰고 `docs/` 폴더에 개발 일지·[변경점](changelog.md)·[보완점](improvements.md)을 모았다. 요구사항과 결정은 PRD에 두고, 써 보며 드러난 한계는 보완점에 두는 식으로 역할을 나눴다.
- 선수 페이지 타격 요약에 빠져 있던 삼진(SO)을 넣었다.

**국제 아마추어 계약 확대**
- 국제 계약 정보가 Pipeline 순위권 선수에게만 있다는 것을 확인했다. 해외 출신 현역 2,967명 중 273명뿐이었다.
- MLB 이동 기록(`/transactions`)에서 MLB 구단과의 첫 FA 계약을 읽어 2,658명을 확인했다. 그 결과 국제 아마추어 계약 2,595명(예: 후안 소토 2015-07-02 워싱턴)의 계약일·구단이 생겼다.
- **문제**: 이동 기록은 2009년 무렵부터만 있다. 그래서 오래된 선수는 첫 계약 대신 나중 FA 계약(예: 2009년 페드로 마르티네스–필리스)이 첫 기록으로 잡혔다.
  **해결**: 계약 연도가 프로 첫 시즌보다 늦거나 2년 넘게 이르면 첫 계약으로 보지 않는다. 23세 미만의 마이너리그 계약만 국제 아마추어 계약으로 표시하고, 나머지는 "FA 계약 (지명 없음)"으로 나눴다.
- 계약금은 이동 기록에 없어 여전히 Pipeline 209명뿐이다.

**포스팅·해외 리그 이적**
- MLB 이동 기록은 야마모토도 그냥 "signed free agent"로 적는다. 포스팅인지와 전 소속팀(오릭스)을 알 수 없었다.
- 위키백과 포스팅 표(NPB·KBO)에서 포스팅 38명의 포스팅 날짜, 전 소속팀, 포스팅 금액, MLB 계약을 가져왔다. 예: 야마모토, 오릭스, $50,625,000, 12년 $325M.
- 일본·한국·대만 출신 MLB 선수 목록에서 포스팅이 아닌 선수는 선수 문서의 소속팀 기록으로 MLB 데뷔 전 마지막 해외 구단을 찾았다. 이렇게 센가, 스가노, 김현수 등 51명을 찾았다.
- **문제**: 최근 포스팅 행은 날짜를 틀 없이 글로 적었다. 김혜성 행은 이름이 정렬 틀 없이 링크로만 있었다. 그래서 김혜성이 포스팅이 아닌 이적으로 잘못 분류됐다.
  **해결**: 두 형식을 모두 읽게 하고 테스트에 넣었다.
- 출처가 포스팅 여부만 구분하므로 "FA"라고 단정하지 않고 "해외 리그 이적 (포스팅 아님)"으로 표시했다. 노모·이라부처럼 옛 임대·판매 이적도 여기에 섞여 있다.

**금지약물 징계 `*` 표시**
- MLB 이동 기록은 징계 선수를 사유 없이 제한 명단(restricted list)으로만 적는다. 이 명단은 개인 사정·비자 문제에도 쓰인다. 그래서 위키백과 금지약물 징계 목록을 썼다.
- 공식 징계 241건 중 233건(212명)을 연결했다. 이름이 한 명에게만 맞고 징계 연도가 그 선수의 경력 기간 안일 때만 연결하고, 동명이인은 투수·야수로 한 번 더 걸렀다. 그래도 구분되지 않는 8건은 표시하지 않았다.
- 징계 없이 이름만 거론된 선수(미첼 보고서 등)는 넣지 않았다.
- 페이지마다 표를 그리는 코드가 달랐다. 그래서 공통 코드(`common.js`)가 화면에 생기는 선수 링크를 찾아 `*`를 붙이게 했다. 리더보드·검색·선수단·수상 등 모든 화면에 한 번에 적용된다.

## 4일차 — 11월 19일 (목) · 수상 기록 바로잡기

**명예의 전당 누락 원인**
- Vladimir Guerrero(2018) 누락을 계기로 Codex의 수상 전수 점검(`docs/awards-audit-2026-11-18.md`)을 다시 확인했다. 보고서는 원본 API부터 8명이 없다고 적었지만 실제로는 필터 없이 요청하면 354명이 모두 온다.
- 원인은 요청의 `sportId=1`이었다. 이 필터는 팀이 없거나 MLB 일반 구단 ID가 아닌 행을 통째로 뺀다. 임원·니그로리그 인물 7명은 팀이 없고, Guerrero는 명판 팀이 옛 "Los Angeles Angels" ID(3823)로 적혀 빠졌다. 34개 상을 비교하니 같은 이유로 2023 Devin Williams(All-MLB 2nd, 팀 USA)와 Andrés Giménez(AL 플래티넘 글러브, 팀 VEN)도 빠져 있었다.
- 상마다 `sportId=1` 응답과 필터 없는 응답을 함께 받는다(요청 34→68회). 행은 모두 남기고, 필터에서만 빠진 행의 팀은 MLB 구단이 아니므로 비운다(대표팀을 수상 구단으로 보여주지 않는다).

**헌액 연도**
- 원본 `season`은 선출 연도다. 12월 위원회 선출(2021-12-05 Golden Days·Early Baseball, 2023-12-03 Leyland)은 헌액이 다음 해다. 원본 날짜가 12월이면 다음 해로 둔다. 옛 행은 날짜가 11-01로 채워져 있어 영향이 없다. `hof_votes.json` 354명의 연도와 모두 일치한다.

**포지션**
- 수상 응답마다 포지션을 덮어써 마지막 월드시리즈 우승 응답의 `X`(알 수 없음)가 빈 값으로 남았다(1,565명). 상마다 OF/CF, P/RP처럼 값도 달랐다. 선수 파일이 있으면 프로필의 주 포지션을 쓰고, 없으면 처음 받은 빈 값이 아닌 수상 포지션을 쓴다. 빈 값은 51명(감독·임원 등)으로 줄었다.

**재생성**: `awards.py` → `hof_votes.py`(누락 8명 득표 정보 연결, 1956·1985·2007 문서는 요청 실패로 이전 값 유지) → `teams.py`(구단 역사 헌액 연도 4건 변경).

**확인한 원본의 함정**
- 타구 CSV에는 BBE가 있어도 측정값이 없는 선수가 있다. 이를 오류로 시즌 전체를 버리거나 0으로 채우지 않고 null로 보존했다. 주요 값이 집계 전체에서 모두 누락되면 실패로 본다.
- Pitch Arsenals CSV는 선택한 지표별 열만 내보낸다. 한 요청에 필요한 지표가 모두 있는 페이지의 공개 JSON 배열을 JSONDecoder로 읽고 JS는 실행하지 않는다.
- 내부 `n_ff` 등은 퍼센트 문자열인데 FO·SC의 `n_fo`·`n_sc`는 0~1 비율이었다. 동일한 방식으로 읽으면 센가·사사키의 구종 사용률 합이 67% 안팎으로 떨어졌다. 표시용 `n_{구종}_formatted`는 모두 백분율이므로 이를 사용하도록 수정하고 혼합 단위 회귀 테스트를 추가했다. 재생성 뒤 모든 선수의 구종 사용률 합은 3개 시즌 모두 99.8~100.2%였다.
- fastball/breaking/offspeed와 6종 묶음은 개별 구종과 중복이므로 제외했다. 반올림 비율에서 정확한 개별 구수를 역산하지 않았다.

먼시의 2012 지명과 모순되는 ‘2009년 이전 이동’은 기록 부재를 연도로 추정한 공통 표시 오류였다. 리그 이동 수집에서 마이너 FA 계약을 제외하여 다저스의 공식 2017-04-28 계약도 빠져 있었다. 원본 거래의 선수 ID·목적지 MLB 구단 ID를 확인하는 별도 보완 수집기를 추가하고, 어떤 선수도 근거 없이 입단 연도를 추정하지 않도록 표시 함수를 분리했다.

## 2026-11-20 — 작업 마무리와 GitHub 반영

### 이번 작업에서 달라진 점

선수의 숫자를 보여주는 데서 같은 시즌의 맥락을 함께 설명하는 방향으로 확장했다. Statcast는 2015~2026의 12개 시즌을 제공하며, 타구 속도·발사각·타구 비율을 선수·MLB 평균·차이의 네 열로 비교한다. 투수는 같은 구종·투구 손끼리 구속·회전수·움직임을 비교한다. 공개 집계의 반올림과 측정 누락을 고려해 평균을 가중 근사치로 명시했다.

자료가 늘면서 선수 페이지가 길어져 프로필 카드에 ‘상세 기록·분석’ 메뉴를 추가했다. 기존 화면에는 선수 정보와 시즌별 기록·계약·이적을 두고, 상세 화면에는 리그 평균·리포트·상황별 성적·Statcast를 모았다. 같은 HTML과 JSON을 공유하며 선수 ID와 분석 시즌을 주소에 남겨 다시 열거나 공유할 수 있게 했다.

계약 자료는 일부 선수의 수동 등록만으로는 누락을 막기 어려웠다. 슈와버의 FA 계약 누락을 계기로 30개 구단 공개 자료와 직접 확인한 자료를 합치는 구조로 바꿨다. 최종 1,220명을 제공하며 명시적인 시즌별 기본 연봉은 53명이다. 금액이 없는 계약의 기간과 미확인 금액을 구분하고, 기존 수동 정정은 수집 결과보다 우선한다.

### 사용자 제보로 확인한 오류와 배운 점

먼시의 2012년 지명 아래에 ‘2009년 이전 이동’이 표시된 것은 단순한 날짜 오기가 아니었다. 마이너 FA 계약이 수집 범위에서 빠진 데다, 화면에서 기록 부재를 특정 연도의 이동으로 단정한 두 문제가 겹쳤다. 현재 구단에 연결된 8,383명으로 점검을 넓혀 마이너 FA 입단 1,943명을 보완했고, 확인하지 못한 403명은 미확인으로 남겼다.

## 2026-11-20 — UI/UX 1차 개선

선수 상세의 요약 재배치, 모바일 핵심 열 보기, 다른 화면 표의 키보드 정렬은 후속 범위다. 이번 변경은 로컬에만 있으며 커밋·푸시·배포하지 않았다. 기존 미커밋 개발 일지 내용은 유지했다.

## 2026-11-20 — UI/UX 2차 개선

선수 상세는 이름·팀과 메뉴 다음에 최근 시즌 핵심 지표·통산 표를 두었다. 기존 요약 계산을 재사용하며 타자와 투수는 위아래로 쌓는다. 최근 제공 시즌을 연도로 명시해 은퇴 선수의 마지막 시즌을 현재 시즌으로 오해하지 않게 했다. 프로필·입단 정보·수상 연혁은 기본 접힘으로 묶고 유망주 배너·금지약물 징계는 접힌 영역 밖에 둔다. 연도별 기록 바로가기와 프로필 내부 해시 목적지의 펼침 처리를 추가했다. 분석 화면은 요약을 숨기고 선택한 분석 시즌 기록을 유지한다.

리더보드에는 핵심·전체 열 보기를 추가했다. 선택이 없으면 640px 이하에서 핵심, 넓은 화면에서 전체를 표시한다. 직접 고른 보기는 URL에 남겨 크기 변경·재접속에도 유지한다. 핵심 보기에서는 포지션 열 대신 주요 수치를 먼저 보고 정렬 지표가 기본 핵심 목록에 없어도 첫 열에 포함한다. 전체 보기의 기존 열 순서·정렬·필터는 유지했다. 긴 이름은 모바일 핵심 보기에서 줄이되 전체 이름은 링크 텍스트·title에 보존하고 징계 별표는 줄임표 밖에 둔다.

로컬 서버 8002에서 검증했다. 오타니 390px 요약 시작 약 362px(이전 검토 1,536px), OPS .889·HR 30과 투구 ERA 1.79·IP 85.2 표시, 프로필·수상 펼치기, 연도별 바로가기 위치 16px, 분석 2025 시즌 전환을 확인했다. 페드로 마르티네스는 2009 시즌·44.2이닝으로 표시됐다. 핵심 HR Enter 정렬과 포커스, 전체 전환 시 HR 유지, NYY·핵심 보기 주소 복원, 세이버·투수 전환, 비핵심 G 정렬의 핵심 보기 보존을 확인했다. 320px에서 첫 정렬 열이 화면 안에 있고 빈 결과의 colspan과 머리글 개수가 일치했다. 1280px 자동 전체→390px 자동 핵심 전환 및 명시적 핵심 선택의 크기 변경 시 유지, Willson Contreras의 별표 노출도 확인했다. 관련 브라우저 오류 로그는 없었다.

`node --check js/leaderboard.js`, `node --check js/player.js`, `git diff --check`를 확인했다. 데이터 생성·수치 계산 변경은 없고 Python 전체 테스트는 실행하지 않았다. 실제 휴대폰·다크 모드·스크린리더, 다른 표의 키보드 정렬은 남는다. 1·2차 변경 모두 커밋·푸시·배포 전이다.

추가 대화에서 투수 투구 위치 분포와 타자 핫·콜드존이 제안됐다. 현재 시즌 집계에는 위치 좌표가 없으며 별도 데이터 수집·집계 설계가 필요한 후보 기능이다. 이번 UI 변경에 포함해 구현한 것으로 간주하지 않는다.

## 2026-11-20 — 투수 탄착군·타자 핫콜드존

사용자의 구현 요청으로 2026 MLB 정규시즌 위치 자료를 추가했다. `zones.py`가 공식 일정과 Baseball Savant 공개 CSV를 3일 단위로 대조하며, 원본 CSV는 메모리에서만 읽고 구역별 분모·결과와 작은 위치 격자의 빈도만 저장한다. 수집 중 실행 환경이 재시작됐지만 정상 구간 캐시부터 이어받았다. 최종 범위는 **2026-09-27 경기일까지 2,429경기·716,792구·선수 1,470명**이다.

마지막 날짜의 경기 1개가 CSV에서 빠져 검증이 중단됐다. 공식 경기 피드를 확인하니 BAL–NYY(823490)는 우천 취소로 투구가 0개였다. 일정 API가 이 경우에도 `abstractGameState=Final`을 줬고 세부 코드가 `C`였다. 취소를 실제 완료 경기에서 제외하는 `completed()`를 추가하고 회귀 테스트로 남겼다. 나머지 구간을 재수집하지 않고 마지막 정상 구간부터 완성했다.

선수 분석에는 구종별 색상의 위치 분포와 구종·상대 타석 필터, 타자 타율·장타율·헛스윙률 및 상대 투구 손 필터를 넣었다. 위치 점은 20×20 격자 중심이며 공별 실제 점·목표 대비 제구 점수가 아니다. 5×5 표 중앙 3×3은 자체 구역 정의이고 외곽 칸은 먼 공도 포함한다. 타석 종료 공에만 타수·안타·루타를 붙이며, 주자 아웃·희생타 등을 타수로 세지 않는다. 실제 0과 0분모·위치 누락을 구별한다. 색은 선택한 조건의 선수 전체 표본 대비이고 소표본은 회색으로 두며 수치·분모·선택 구역의 상세를 제공한다.

현재 버전의 화면용 버킷 합계는 약 13.5MB, 가장 큰 파일은 237,766바이트다. 브라우저는 제공 시즌 색인과 해당 시즌 색인, 선수 ID 끝 두 자리의 버킷 하나만 읽는다. 새 버킷의 내용 해시를 파일명으로 쓰고 모든 파일을 저장한 뒤 색인을 교체하며 직전 버전도 한 세대 유지한다. 구간 집계 캐시는 약 56.05MB이며 배포에서 제외한다. 캐시를 재사용할 때 원본 수집 시각(`updated`)을 바꾸지 않고 이번 확인(`checked`)과 구별한다. 일일 갱신 단계와 실패 코드 알림에 포함했으며 실제 Actions 실행·배포는 아직 확인하지 않았다.

### 검증

- Python 전체 135개, Node 전체 16개 테스트 통과. 좌표 경계, 누락값·실제 0, 타율·장타율·헛스윙률의 서로 다른 분모, 중복·상충 투구, 누락 경기·진행 중 경기·취소 구분, 수집 실패 보존, 파일 쓰기 실패 시 이전 색인 보존, 캐시 수집 시각 유지, 시즌 전환 경쟁을 검증했다.
- 생성된 전 선수·분할의 투구 합계, 구역 합계, 격자+그림 밖 합계, 헛스윙≤스윙≤투구, 안타≤타수, 안타≤루타≤4×안타를 검사해 오류 0건이었다. 투수·타자 양쪽 합계가 각각 716,792구이고 위치·존 높이 누락은 각각 2,677구다.
