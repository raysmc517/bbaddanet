# UI/UX 검토 — 2026-11-20

## 범위와 방법

UI/UX Pro Max의 표·키보드 포커스·터치 대상 지침을 참고해 현재 HTML/CSS/JavaScript와 PRD를 대조했다. 브라우저에서는 GitHub Pages의 리더보드, 오타니 선수 정보·분석, 순위, 전체 선수 검색을 확인했다. 모바일은 390×844 CSS px로 확인했으며 실제 휴대폰 테스트는 아니다.

로컬 HTTP 서버 접속은 브라우저에서 연결 시간 초과로 실패했다. 따라서 화면 관찰은 배포본, 코드 근거는 작업 폴더 기준이며 둘이 완전히 같은 빌드라고 보장하지 않는다. 전체 페이지·전체 선수·다크 모드·스크린리더·네트워크 실패 상황을 전수 검증한 결과는 아니다. 코드와 데이터는 변경하지 않았다.

## 종합 판단

녹색 계열과 절제된 표 중심 구성은 야구 기록 조회 목적에 맞는다. 이름·순위 고정, 숫자 정렬, 기본/세이버 분리, 주소에 남는 조회 조건은 유지할 만하다. 개선 효과가 큰 부분은 주요 기능의 발견성, 선수 정보의 우선순위, 입력 방식에 따른 접근성이다.

## 우선순위별 발견 사항

### 1. 높음 — 표 정렬을 키보드로 실행할 수 없다

- 근거: `js/leaderboard.js`의 `renderHead()`는 일반 `<th class="sortable">`를 만들고 머리글의 click 이벤트만 처리한다. 배포 화면에서도 정렬 머리글의 `tabIndex`가 -1이며 안에 버튼이 없다.
- 영향: Tab으로 열 정렬에 도달하거나 Enter/Space로 실행할 수 없다. `aria-sort`는 정렬 상태를 알려주지만 조작 수단을 제공하지 않는다.
- 개선: 머리글 안에 실제 버튼을 두고 현재 정렬 상태를 머리글에 유지한다. 재렌더링 뒤에도 누른 버튼으로 포커스를 복원한다.
- 완료 기준: 마우스와 키보드 모두 같은 정렬 결과를 내고, 방향 전환 후 포커스가 사라지지 않는다.

### 2. 높음 — 모바일에서 전체 선수 검색 메뉴가 숨는다

- 근거: 390px 리더보드에서 메뉴의 보이는 너비는 358px, 내부 너비는 422px였다. ‘선수 검색’은 처음 화면에 보이지 않았다. `css/style.css`는 메뉴 가로 스크롤을 허용하면서 스크롤바를 숨긴다. 선수 상세의 메뉴는 항목이 하나 더 많다.
- 영향: 첫 방문자는 리더보드 안의 검색만 보고 은퇴 선수를 찾는 전체 검색 기능을 놓칠 수 있다.
- 개선: 모바일에서 선수 검색을 고정 노출하고 나머지 메뉴는 더보기로 묶거나, 가로 이동을 알리는 명확한 표시를 둔다. 리더보드 검색은 ‘현재 시즌 이름 검색’, 전체 검색은 ‘전체 선수 검색’처럼 범위를 구별한다.
- 완료 기준: 390px 첫 화면에서 전체 선수 검색에 접근할 수 있고 다른 메뉴가 있다는 사실도 보인다.

### 3. 중간 — 선수의 현재 기록보다 상세 이력이 먼저 길게 나온다

- 근거: 오타니의 390px 화면에서 수상 경력 제목은 문서 상단 약 895px, 시즌·통산 요약은 약 1,536px, 연도별 타격 기록은 약 2,065px에 있었다. 프로필 세부 사실과 수상 이력이 요약보다 앞선다. 수치는 해당 선수와 검토 환경에서의 관찰값이다.
- 영향: 현재 시즌 성적을 보려고 들어온 사용자가 여러 화면을 내려야 한다. 분석 화면도 공통 프로필을 먼저 거친다.
- 개선: 이름·팀·주요 시즌 지표를 먼저 배치하고 상세 입단 정보·수상 연혁은 펼쳐보기로 둔다. 기록·분석·계약·이적에 바로 가는 페이지 내 링크를 제공한다.
- 완료 기준: 모바일에서 현재 시즌의 핵심 지표를 빠르게 보고 원하는 상세 구역으로 이동할 수 있다.

### 4. 중간 — 지표 설명이 hover용 title에 의존한다

- 근거: `js/leaderboard.js`의 열 정의 설명은 머리글 `title`에 들어간다. `js/common.js`에는 간이 WAR·wRC+·FIP 설명이 있지만 리더보드에서 이를 터치로 여는 별도 조작은 없다. 용어 설명 페이지 미구현은 기존 보완점에도 기록돼 있다.
- 영향: 터치 사용자가 약어 뜻과 간이 지표의 한계를 확인하기 어렵다. 정렬 동작과 설명 확인 동작도 구별되지 않는다.
- 개선: ‘지표 설명’ 버튼으로 현재 보기의 설명 목록을 열거나 별도 도움말로 연결한다. 정렬 버튼과 도움말 조작은 분리한다. 선수 이름의 징계 별표도 표 근처에 짧은 범례를 둔다.
- 완료 기준: hover 없이 지표 정의와 간이 WAR의 차이를 읽을 수 있다.

### 5. 중간 — 넓은 기본 표에서 정렬 기준과 주요 비율 기록을 찾기 어렵다

- 근거: 기본 타격 표는 순위·이름·팀·포지션 뒤에 17개 지표를 표시하며 기본 정렬은 마지막 OPS 열이다. 390px 화면에서는 초기 위치에 이름·팀·포지션·G·PA 정도가 보인다. 순위 표도 341px 영역에 약 877px 이상의 내용을 담는다.
- 영향: 표를 열었을 때 무엇을 기준으로 순위가 매겨졌는지, 주요 비율 기록이 어디 있는지 바로 알기 어렵다. 가로 스크롤 자체는 필요한 기능이다.
- 개선: 표 위에 ‘OPS 높은 순’처럼 정렬 기준을 표시하고 모바일용 핵심 열 보기를 추가한다. 전체 열과 가로 스크롤, 이름 고정은 유지한다. 열 순서 변경은 기존 표 순서 요구와 함께 결정한다.
- 완료 기준: 가로로 이동하기 전에도 정렬 기준을 알며 핵심 기록/전체 기록을 선택할 수 있다.

### 6. 중간 — 리더보드 검색의 범위와 필터 해제가 충분히 설명되지 않는다

- 근거: 입력 라벨은 ‘선수 검색’, placeholder는 ‘이름’이다. 검색 시작 시 팀·포지션·최소 출장 조건은 의도적으로 해제되지만 시즌·레벨은 유지된다(`js/leaderboard.js`). 빈 결과에는 ‘조건에 맞는 선수가 없습니다’만 표시한다. 별도 전체 검색은 은퇴 선수도 찾는다.
- 영향: 시즌에 기록이 없는 선수와 사이트 전체에 없는 선수를 혼동할 수 있다. 검색을 지운 뒤 최소 출장 조건이 ‘전체’로 남는 이유도 쉽게 알기 어렵다.
- 개선: 검색 범위를 라벨에 명시하고 조건 해제 시 짧게 알린다. 빈 결과에는 적용 중인 조건, 초기화, 전체 선수 검색 링크를 제공한다. 현재 동작은 PRD의 사용자 결정이므로 임의로 바꾸지 않는다.
- 완료 기준: 사용자가 검색 대상과 현재 적용된 조건을 파악하고 빈 결과에서 다음 행동을 선택할 수 있다.

## 확인한 좋은 동작

- Ohtani 검색 뒤 타석 조건이 전체로 바뀌고 결과 1명을 표시했다. 반대쪽 투수 기록으로 이동하는 안내도 나타났다.
- 리더보드에서 선수 페이지에 진입했을 때 리더보드 링크가 이전 검색 주소를 가리켰다.
- 선수 정보와 상세 분석 간 이동이 가능했고 Statcast에 근사 평균·출처·단위·해석 한계를 표시했다.
- 전체 검색의 Pedro Martinez 입력은 악센트 유무와 관계없이 두 동명이인을 각각의 ID 링크로 표시했다.
- 확인한 모바일 리더보드·선수·순위에서 표는 내부 가로 스크롤을 사용했다. 화면 전체를 표 너비로 넓히는 형태는 관찰되지 않았다.

## 권장 작업 순서

1. 정렬 버튼의 키보드 접근과 모바일 전체 검색 노출.
2. 검색 범위 안내·빈 결과·지표 설명.
3. 선수 상단 요약 재배치와 핵심 열 보기.

다음 구현 때 390px·데스크톱에서 정렬, 필터, 검색, 선수 링크, 뒤로 가기, 표 가로 스크롤을 재검증하고 다크 모드·키보드 포커스도 확인한다. 이번 검토만으로 UI 구현 변경을 확정하지 않는다.

## 후속 구현 — 2026-11-20

사용자의 개선 착수 요청에 따라 1차 변경을 로컬 코드에 반영했다. 공통 메뉴의 전체 검색 우선 노출, 리더보드 키보드 정렬·포커스 유지, 검색 범위·적용 조건·현재 정렬 안내, 빈 결과 복구와 지표 설명 펼치기를 추가했다. 위의 관찰은 변경 전 검토 기록이며 현재 남은 범위는 [보완점](improvements.md), 로컬 검증 결과는 [개발 일지](devlog.md)의 UI/UX 1차 개선에 정리했다. 선수 상세 요약 재배치와 모바일 핵심 열 보기는 아직 구현하지 않았다.

### 2차 개선 완료

후속 요청으로 선수 상세 요약 재배치와 모바일 핵심 열 보기도 로컬에 반영했다. 오타니의 390px 화면에서 요약 시작은 약 362px이며 기존 검토의 1,536px보다 앞당겨졌다. 핵심 기록은 정렬 지표를 첫 수치 열로 두고 전체 보기 전환에도 조건을 유지한다. 320px·390px 및 1280px에서 보기 동작과 선수 정보·분석 전환을 확인했다. 위 본문의 미구현 표기는 각 단계의 당시 상태이며 현재 상태는 PRD와 개발 일지를 따른다.
